Dam Screening Tool

Event Trees

An event tree evaluates a failure mode as a sequence of nodes: the team chooses the reservoir stages, assigns each node a probability at each stage with a rationale, and DST reports the resulting system response. PFM-11, PFM-12, PFM-13, PFM-17, PFM-18, PFM-20, PFM-22 and PFM-23 use an event tree, as does PFM-21 when the dam has a concrete type but no Gravity or Roller-Compacted Concrete type (see PFM-21: Concrete Dam Instability). DST multiplies the node probabilities along each pathway to breach. Common problems at the end of this page explains why the curve does not appear or is not passed to the Risk Analysis module.

An event-tree page has the sections 1 Stages to evaluate, 2 Event tree evaluation and System Response. Each failure mode's page in this guide lists its own stages, nodes, questions and branches. The SRP mode control reads Event tree and User defined (see Active SRP).

Every entry on an event-tree page saves automatically and clears the location's verification. A change to a source of a default stage, such as the normal pool on the Stage Duration page, also clears it.

Stages​

The Stages to evaluate section sets the reservoir stages at which the tree is evaluated, lowest first. At and below the zero point, the system response is fixed at 1.00E-16 and nodes take no probability.

Figure shows the section, and Table describes its columns.

Table: Stages to evaluate columns
FieldUnitsRequiredDescription
Zero point—RequiredThe stage at and below which the system response is fixed at 1.00E-16. Default: the lowest stage. Stages at or below it are grayed.
ElevationftRead-only or RequiredDefault stages: taken from their source, or Source missing until the source is complete. Added stages: entered by the user.
Stage—Read-only or OptionalThe stage name. Added stages: a description of up to 200 characters; a blank description becomes Added stage.
Source—Read-onlyWhere a default stage comes from, for example "Spillway crest, Dam Data", or "Added, every node" or "Added, Node 3 only" for an added stage.

Default stages come from the failure mode and cannot be edited or deleted. To add a stage for every node:

  1. 1The user selects Add stage. A new row opens with an elevation box and a Description box.
  2. 2The user enters the elevation and, optionally, a description.
  3. 3Pressing Enter, or leaving the row, adds the stage in elevation order. Escape or the × button cancels it.

An added stage's elevation and description stay editable in place. The trash icon deletes the stage with its entered values. A stage added from a node's panel applies to that node only (see Nodes).

The Zero point column chooses one stage. When the lowest stage is chosen, the zero point follows whichever stage is lowest, so adding a stage below it moves the zero point down to the new stage. Choosing any other stage fixes the zero point there. Deleting the added stage that holds the zero point returns the zero point to the lowest stage.

Event tree diagram​

The diagram in the Event tree evaluation section shows which nodes are complete and opens each node for entry. The section's heading counts the complete nodes, for example "3 of 5 nodes complete".

Figure shows the diagram with a node selected, and Table describes each numbered region.

Table: Event tree evaluation regions
#RegionDescription
1DiagramThe tree from the flood loading to breach. Selecting a node opens its panel.
2Selected nodeThe node whose panel is open.
3ProbabilityThe node probability at one stage, from 0 to 1.
4SliderSets the same probability on a scale of verbal descriptors.
5Estimate rationaleThe case for the node's estimates, across all of its stages.
6Previous node, Next nodeMove to the previous or next node.

Each node's circle shows its state:

  • Its number: not started.
  • An amber ring: started; some values or the rationale are entered.
  • A check: complete; it has a probability at every stage above the zero point and an estimate rationale.

In a tree with more than one pathway, the line splits after the branching node into a Yes row and a No row. A node that mirrors another is tagged Mirrors or Partly mirrors beneath its title (see Mirrored nodes).

Nodes​

Each node's probability at each stage, and the rationale for its estimates, are entered in the node panel. The panel is headed with the node's number, title and question. It has one row per stage of the node: the default stages, the stages added for every node and the stages added for this node only. A node that does not depend on the stage has a single row, All stages, marked Pool independent. Table describes its inputs.

Table: Node panel inputs
FieldUnitsRequiredDescription
Probability—Required: every stage above the zero pointThe probability of the node's Yes outcome at the stage, from 0 to 1. Saves when the user leaves the box; a 0 is stored as 1.00E-16. Stages at or below the zero point show a dash and take no value.
Slider—OptionalSets the probability by dragging, on a scale marked Virtually Impossible (0.001), Very Unlikely (0.01), Unlikely (0.1), Neutral (0.5), Likely (0.9), Very Likely (0.99) and Virtually Certain (0.999). A value set with it saves at once.
Estimate rationale—RequiredA rich-text case for the node's estimates across all of its stages. Saves shortly after the user pauses typing.

The slider and the Probability box set the same value. The slider moves between its seven stops only; the box takes any value from 0 to 1, and a typed value between two stops places the slider's handle between them. An empty box leaves the slider without a handle. A node's probabilities should stay the same or increase from one stage to the next.

Add stage to this node adds a stage that only this node uses; the user enters it in the same way as an added stage (see Stages), and it appears in the Stages table as Added, Node N only. Its trash icon deletes it with its value. Pool-independent nodes have no such button.

Previous node and Next node step through the nodes, starting with those shared by every pathway and then following each pathway.

tip

Tab moves between the nodes of the diagram, and Enter or Space opens one, so a tree can be worked through from the keyboard. Next node moves to the next node without returning to the diagram.

Mirrored nodes​

In trees whose pathways repeat a node, the repeated node can mirror its source node, so the team enters the values once. Mirroring is off by default. The node panel of such a node has a check box, for example Mirror Node 2a:

  • Turning it on. The node follows its source's values and rationale. Mirrored values show a link icon ("Mirrored from Node 2a"), and the rationale shows "Shared with Node 2a until you edit it here."
  • Overriding one stage. Entering a value at a stage overrides it for that stage only, and the node becomes Partly mirrors. The re-link icon beside the overridden value discards it and follows the source again. Re-link all discards every override of the node.
  • Editing the rationale on the mirroring node replaces the shared rationale with its own.

Event tree system response​

The System Response section of an event-tree page shows a table and a chart once every node has a probability at every stage above the zero point and the stages and probabilities have no errors.

Figure shows the results of a tree with two branches.

  • Table. One row per stage, with one column per branch (Branch a, Branch b) when the tree has more than one pathway, and Total SRP. The information icon on a branch header names the pathway's nodes; the icon on Total SRP explains how the branches combine. Resting the pointer on a branch value shows its share of the total, such as "62.5% of the total". Stages at or below the zero point are grayed.
  • Chart. The curves plotted against Pool Elevation (ft) on a logarithmic probability axis, with the same zoom, reset and download controls as the other SRP charts (see SRP charts).

The total becomes the location's active SRP in Event tree mode. Event-tree pages have no nodal revisions; the team enters the node probabilities directly.

How the total is calculated​

At each stage above the zero point, each branch is the product, along its pathway, of P for each step that takes a node's Yes outcome and 1 − P for each step that takes its No outcome, where P is the node's probability at the stage. The Total SRP is the sum of the branches. A branch or total below 1E-16 is raised to 1E-16.

For example, take a tree with two pathways through Nodes 1, 2 and 3, one taking Node 3's Yes outcome and the other its No outcome. With Node 1 at 0.1, Node 2 at 0.5 and Node 3 at 0.2 at a stage, Branch a is 0.1 × 0.5 × 0.2 = 0.01, Branch b is 0.1 × 0.5 × 0.8 = 0.04, and the total is 0.05.

At a stage added for another node only, DST interpolates a node's probability between its own stages, linearly in elevation and in the logarithm of the probability, starting from 1E-16 at the zero point, and holds it above the node's highest stage.

Common problems​

These problems apply to every event-tree page. For problems shared with the other failure mode pages, such as verification being cleared, see Common problems on the Failure Mode Pages page.

  1. The System Response section reads "No system response curve yet" and "The curve appears once every node has a probability at every stage above the zero point and the stages and probabilities have no errors." The diagram shows which nodes are not complete, and the page messages list the errors. The user enters the missing probabilities, including at any added stage, and corrects the errors; the curve then appears.

  2. The message "The total system response decreases from [stage] to [stage], so it is not published to risk." means the results show on the page, but the location has no active SRP for the Risk Analysis module. A node's probability that drops between stages is the usual cause, reported as "Node [n] – [title] decreases from [stage] to [stage]." The user raises the lower value, or lowers the higher one, so that each node stays the same or increases with stage.

  3. The page the stage comes from does not yet provide it, for example the normal pool on the Stage Duration page or the spillway crest on the Dam Data page. The Source column names the page; the user completes the value there.

  4. Default stages come from other pages and cannot be edited or deleted on the event-tree page. The user changes the value on the page named in the stage's Source column and then moves the stage from the notice (see A notice says a stage source changed), or adds a stage at the needed elevation (see Stages).

  5. When the source of a default stage changes, a notice above the stages table reads, for example, "The Normal Pool source changed. It now resolves to 1,021.50 ft. The stage stays at 1,018.00 ft until you move it." Move stage to (with the new elevation) moves the stage; Dismiss keeps it where it is.

  6. Each stage needs its own elevation, and an added stage must lie between the lowest and highest stages. The user changes the added stage's elevation or deletes it with its trash icon.

  7. On the event-tree pages that read a cross section, DST refuses a Cross Section that does not suit the failure mode: "Choose an earth embankment cross section for this failure mode.", "Choose a concrete cross section for this failure mode." or "Choose a gated concrete cross section for this failure mode." A section deleted in another session reads "The selected cross section no longer exists. Reload the page and choose another." The user chooses a suitable section, adding one on the Dam Information page if needed (see No usable cross sections).

  8. DST refuses with "The event tree has no system response yet. Complete every node's probabilities and resolve the errors on this page, then verify." until the curve appears (see No system response curve yet).
