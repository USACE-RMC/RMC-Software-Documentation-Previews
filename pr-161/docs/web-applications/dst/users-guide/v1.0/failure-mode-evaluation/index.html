Dam Screening Tool

Failure Mode Evaluation

The Failure Mode Evaluation page, under the Response module, lists every potential failure mode (PFM) the screening team selected for evaluation on the Failure Mode Selection page (see Chapter 10, Failure Mode Screening and Selection). From it, the user adds the locations at which each PFM is evaluated and opens each location's failure mode page. On that page the user characterizes the location and defines its system response probability (SRP), the curve that the Risk Analysis module uses for that location.

This chapter describes the Failure Mode Evaluation page and the parts that every failure mode page shares: locations, the page toolbar, the characterization pattern, parameter overrides and justifications, the Failure mode summary, the system response with its nodal tables and nodal revisions, and the event tree used by PFM-11, PFM-12, PFM-13, PFM-17, PFM-18, PFM-20, PFM-22 and PFM-23, and by PFM-21 for a concrete dam with no Gravity or Roller-Compacted Concrete type. Chapters 12 through 30 describe each failure mode page's own inputs and refer back here for the shared parts. The DST Technical Reference Manual and the System Response Library manuals document the methods behind each SRP.

The Failure Mode Evaluation Page​

The user opens the page from Response > Failure Mode Evaluation. The page has two columns: the table of selected failure modes on the left and the System Response Preview on the right. On tablets and phones only the table is shown.

The page itself has nothing to verify. The team verifies each location on its own failure mode page (see Verifying a location), and the dot after Failure Mode Evaluation in the sub-navigation turns green only when every location is verified (see Chapter 4, Working in DST).

The failure mode table​

The table, headed Selected Failure Modes, lists the failure modes in the order of the Failure Mode Selection page. Each row names its failure mode by number and name, for example 01 - Embankment Overtopping Erosion. A failure mode with one location has one row. A failure mode with two or more locations has a shaded parent row, followed by one indented row per location, labeled with a letter after the number, for example 02a - Left Abutment and 02b - Right Abutment.

Table describes the columns.

Table: Selected Failure Modes table columns

Resting the pointer on it shows "The DST recommendation changed. Confirm your decision on the Failure Mode Selection page to evaluate this failure mode." Selecting it opens the Failure Mode Selection page (see Chapter 10, Failure Mode Screening and Selection).

The system response preview​

The System Response Preview card plots the active SRP of every Defined location on one chart, so the team can compare them. The chart is read-only; the team defines each curve on its own failure mode page. The subtitle counts the curves, for example "Showing 3 of 3 curves · read-only". The horizontal axis is Headwater Elevation (ft); DST places curves defined against overtopping depth on it using the location's crest elevation.

Figure shows the Curves list, which opens from the button in the chart's upper right corner.

  • Showing and hiding curves. A check box beside each curve shows or hides it; a failure mode's group check box shows or hides all of its locations. Show all and Hide all act on every curve. When every curve is hidden, the chart reads "All curves are hidden. Use Curves to show them." The choice is not saved and resets when the page reloads.
  • Curves not yet drawn. The list shows a location that is Incomplete or Not started with its status and an Open link to its failure mode page. A location whose cross section has no crest elevation shows a No crest tag: DST cannot place its overtopping curve on the elevation axis.
  • Highlighting. Resting the pointer on a curve in the list or in the key below the chart highlights that curve.
  • Empty chart. Before any location is Defined the chart reads "No system response defined yet". When no failure mode is selected for evaluation it reads "Complete Failure Mode Screening and Failure Mode Selection to choose failure modes for evaluation."

Linear and Log, in the chart's upper right corner, switch the Probability axis between a linear and a logarithmic scale; DST picks the scale that suits the curves when the page opens. The chart zooms and resets in the same way as the SRP charts on each failure mode page (see SRP charts).

Locations​

A location is one place on the dam at which a failure mode is evaluated, such as one abutment, one conduit or one cross section. Each location has its own failure mode page, inputs, system response and verification. A failure mode starts with one location when it is selected for evaluation.

The row menu (three dots) at the end of each row holds the location actions. Figure shows the menu of a location row, and Table lists the menu items.

Table: Row menu items
ItemAppears onAction
Open failure modeEvery row except a parent rowOpens the failure mode page of the location.
Add locationA failure mode with one locationAdds a second, empty location.
Copy locationA failure mode with one location, and every location rowAdds a location that copies the row's inputs and results.
Rename locationLocation rowsOpens the Rename location dialog.
Delete locationLocation rowsDeletes the location.

Some failure modes allow only one location. For these, the table offers neither Add location nor Copy location, and the failure mode's chapter says so. Locations that DST creates from the screening's data, such as one location per abutment, cannot be renamed or deleted from the table. The menu shows no location actions to users who cannot edit the screening's inputs, and while inputs are locked (see Chapter 4, Working in DST).

Adding a location​

For a failure mode with one location, the user chooses Add location from its row menu. For a failure mode with several locations, the user selects Add location (+) on its parent row. The + appears only while the failure mode can take more locations: failure modes limited to one location the team adds, such as those whose locations DST creates from other pages, never show it. It is also hidden while the failure mode needs confirmation on the Failure Mode Selection page, and for users who cannot edit the screening's inputs or while inputs are locked. DST adds a location with no inputs, named Location N, where N is the new number of locations, and the table shows the failure mode's locations as indented rows. DST creates the location at once, and its status reads Incomplete until its system response is defined.

Copying a location​

Copy location adds a location that starts with the same inputs, overrides, justifications and results as the row it was copied from. DST names it after the source with (copy) added, for example Left Abutment (copy). The copy is not verified. For a failure mode with one location, the copy is made from that location.

Renaming a location​

Each location's name appears in the table, in the breadcrumb and on its Submission Readiness tile. The user renames a location in the Location box of its failure mode page (see The page toolbar). DST does not save a blank name: system-response pages show "Name cannot be empty.", and event-tree pages keep the last saved name. Location N is only the label DST shows for a location stored without a name.

Rename location in a location's row menu opens the Rename location dialog with a Location name box. SAVE shows the new name in the table, and CANCEL closes the dialog without a change. A blank name leaves the name unchanged.

note

A name entered in the Rename location dialog shows in the table only until the page reloads. To keep a new name, the user enters it in the Location box of the failure mode page.

Deleting a location​

Delete location in a location's row menu removes that location with its inputs, results, justifications and verification. A failure mode always keeps at least one location, so the item appears only on failure modes with two or more locations. Links from the location to files on the Documents page are removed; the files themselves remain (see Chapter 6, Documents).

caution

Delete location acts at once, with no confirmation, and cannot be undone.

Opening a location​

Selecting a failure mode or location name, or Open failure mode in its row menu, opens the location's failure mode page. The sub-navigation then shows a breadcrumb such as Failure Mode Evaluation › PFM-01 · Left Abutment; selecting Failure Mode Evaluation returns to the table (see Chapter 4, Working in DST). Before leaving a failure mode page, DST saves any entry still in progress.

A failure mode page opens only while its failure mode is selected for evaluation. Otherwise the page shows the notice "PFM-01 isn't being evaluated" (with the failure mode's number), reading "This failure mode isn't selected for evaluation on Failure Mode Selection. Select it for evaluation there to open its locations." When the DST recommendation for the failure mode has changed and is not yet confirmed, opening the page returns the user to the Failure Mode Selection page with a notice such as "The DST recommendation for PFM-01 changed. Confirm your decision on the Failure Mode Selection page before evaluating it."

The Failure Mode Page​

Every failure mode page has the same frame: a heading with the failure mode's full name, a toolbar, the page's sections in order, and the Failure mode summary tray along the bottom of the screen. The sections between the toolbar and the tray belong to each failure mode, and its own chapter describes them. Most failure mode pages have one or more characterization sections followed by a System Response section; the event-tree pages instead have Stages to evaluate, Event tree evaluation and System Response (see Event Trees).

Inputs on a failure mode page save automatically (see Chapter 4, Working in DST), and the system response recalculates automatically when an input changes (see Chapter 4, Working in DST). The page messages button lists the page's errors, warnings and required inputs (see Chapter 4, Working in DST).

The page toolbar​

The gray toolbar below the heading identifies the location and chooses how its SRP is defined.

Figure shows the heading and toolbar of a failure mode page, and Table describes its inputs.

Characterization​

The characterization sections describe the location in the terms the failure mode's model uses. Every failure mode page builds these sections from the same kinds of element:

  • Read-only facts. Values DST takes from other pages, such as the embankment height and slopes from the selected cross section or elevations from the Dam Data page. They show a dash until the source page provides them. To change one, the user edits it on its source page.
  • Screening facts. Answers from the Failure Mode Screening questionnaire that the model reads. The information icon beside each names its source, for example From Failure Mode Screening, step 4, with a link to that step. An unanswered question reads Not answered.
  • Entered inputs. Values the user enters or chooses on the page. Each failure mode's chapter lists their ranges and defaults.
  • Inputs with a DST default. Inputs that DST fills in, such as a material taken from the cross section drawing, carry an Auto badge. Resting the pointer on the badge explains where the value comes from. When the user changes the value, the badge reads Manual and a revert button (circular arrow) beside it restores the DST value.
  • Figures. Many pages draw the selected cross section or a profile of the location, with the zones and dimensions the model uses highlighted. They update as the inputs change.
  • Information icons. Selecting the icon beside a label opens a short explanation of what the input represents to the model.

Changing a characterization input recalculates the system response, which clears any nodal revisions of the location (see Nodal revisions).

Parameter overrides​

Most failure mode pages end their characterization with a collapsed overrides section, such as Advanced erodibility overrides. It holds the model parameters for which DST supplies a screening default, each shown as a distribution card.

Figure shows an open overrides section.

  • Opening. Selecting the section's title opens or closes it. Its title shows a count such as 1 overridden, and, when a justification is missing, 1 needs justification in amber.
  • Distribution cards. Each card has a Distribution drop-down and boxes for the distribution's parameters, with a small chart of the distribution beside them; resting the pointer on the chart enlarges it. A Deterministic distribution takes a single value and shows no chart. Some parameters stay at their defaults until a site-specific distribution is chosen; the section's description says when.
  • Reverting. Revert to defaults at the top of the section restores every parameter in it. Where a card shows Revert to default, it restores that one parameter.

Every overridden parameter needs a justification (see Justifications). Changing an override recalculates the system response.

Justifications​

Each value that departs from the DST default needs a written justification: a parameter override, an input with a Manual badge that carries a justification chip, and every node with a nodal revision. The chip beside the value reads Add justification (amber) until a justification is entered and Justification afterward. Selecting it opens a box for the text, which saves when the user leaves it.

The Failure mode summary tray collects all justifications of the location (see Failure mode summary), where they can also be entered. A missing justification leaves the location Incomplete on the Submission Readiness page (see Chapter 4, Working in DST).

Failure mode summary​

The Failure mode summary tray sits along the bottom of every failure mode page. Collapsed, it shows its title and a status such as "1 Unknown · 2 overrides · 1 needs justification · No rationale yet", in amber while a justification is missing. Selecting the strip opens the tray at half height; the tray opens, resizes and closes like the other summary trays (see Chapter 4, Working in DST). Figure shows the open tray.

Verifying a location​

A member of the screening team verifies each location on its own failure mode page with the verification badge at the right of the sub-navigation bar (see Chapter 4, Working in DST). Resting the pointer on the badge names the unit being verified, for example PFM-01 SRP — Left Abutment. In DST Based SRP or Event tree mode, verification needs a current calculated system response. When there is none, DST refuses with "There are no calculated results to verify yet." (on event-tree pages, "The event tree has no system response yet. Complete every node's probabilities and resolve the errors on this page, then verify."). For results from an older model version it refuses with "The SRP cannot be verified because the stored results were produced by an older System-Response model version. Recalculate the results before verifying them." A user-defined SRP needs no calculation to be verified.

Any saved change on the page clears the location's verification: its name, cross section, SRP mode, characterization inputs, overrides, nodal revisions, user-defined SRP, justifications or system response rationale. A change on another page that clears the location's results also clears its verification.

Submission readiness​

Each location has its own tile on the Submission Readiness page, such as PFM-01 · Left Abutment (see Chapter 4, Working in DST). The page lists what keeps a location from being ready, with the failure mode and location first: each error and required input of the page, for example "PFM-01 — Left Abutment: Select a cross section for this location.", and a system response that has not been calculated or is out of date. For an event-tree location in Event tree mode it also counts the incomplete nodes, for example "PFM-11 — Location 1: 2 nodes missing probabilities, 3 missing rationales." A missing justification or system response rationale leaves the location Incomplete.

System Response​

The System Response section shows the location's SRP: the probability of the failure mode's system response at each headwater elevation (or at each overtopping depth, on PFM-01). DST calculates it automatically once the characterization is complete.

Figure shows a calculated system response with a nodal revision, and Table describes each numbered region.

Table: System Response section regions
#RegionDescription
1SRP tableThe system response at up to eight headwaters. Read-only (see Nodal tables).
2SRP chartThe full system response curve (see SRP charts).
3Copy and downloadCopies the curve data for a spreadsheet, or downloads the SRP curves as a CSV file.
4Nodal System ResponseThe node cards, collapsed by default (see Nodal revisions).

While the system response recalculates, the chart shows a placeholder curve. Some pages show an input above the table that sets the range of the curve, such as the maximum depth evaluated; each failure mode's chapter describes it.

Active SRP​

The SRP mode in the toolbar chooses the location's active SRP: the curve DST passes to the Risk Analysis module and shows in the System Response Preview.

  • DST Based SRP (Event tree on the event-tree pages): the curve DST calculates from the page's inputs, including any nodal revisions.
  • User Defined SRP (User defined): a curve the user enters in a table (see User-defined SRP). The page replaces its characterization and system response sections with the table and its chart.

DST keeps both curves. Switching the mode back restores the inputs, results and revisions of the other mode. Switching the mode clears the location's verification. In DST Based SRP mode, the active SRP is ready only when the results are current (see Calculation currency).

SRP charts​

Every system response chart works the same way:

  • The legend inside the plot names each curve: DST Estimate, and Revised Estimate once a node is revised. Pages with more than one pathway plot one curve per pathway, such as Toe Pathway and Daylight Pathway.
  • Resting the pointer on a curve shows its values at that point.
  • The mouse wheel, or a pinch on a touch screen, zooms the chart; dragging pans it. Reset zoom restores the full view.
  • Copy SRP curve data for spreadsheets copies the curve values to the clipboard, and Download SRP curves as a CSV file downloads them. Both appear only when the results are current.

Nodal tables​

A system response is built from a sequence of nodes, each the probability of one event in the failure mode. The SRP table summarizes the total at up to eight headwaters, which DST chooses to preserve the shape of the full curve; a curve with few distinct points has fewer rows. The table has the columns Headwater Elevation (ft) (or the page's horizontal axis) and System Response Probability. Once a node is revised, the second column becomes DST Estimate and Revised Estimate, and the cells of revised rows are tinted. The table is read-only; the Revised Estimate column fills from the nodal revisions.

Below the table, Nodal System Response opens to show one card per node. Each card names its node and what it represents, shows its probability range across the eight headwaters (or its single probability, for a node that does not vary with headwater), and carries a DST tag, or a Revised tag once the node is revised. A revised card also reads Needs justification or Justification provided.

Figure shows the node cards.

Nodal revisions​

A nodal revision replaces DST's estimate for a node with the team's own, at some or all of the headwaters. Selecting a node card opens the node's dialog (Figure), with the node's table on the left and its chart on the right; Table describes its inputs. The information icon beside the dialog's title explains how the eight headwaters are chosen.

Table: Node dialog inputs
FieldUnitsRequiredDescription
Headwater ElevationftOptionalThe eight headwaters at which the node is tabulated. Editable; values must increase down the table. An edited headwater is tinted. A node that does not vary with headwater shows All Pools.
DST Estimate—Read-onlyDST's estimate at each headwater, in scientific notation.
Revised Estimate—OptionalThe team's estimate, from 0 to 1. Blank by default. Once one cell holds a value, the other cells show the DST estimate in gray italics until they are changed.
Justification for Revision—Conditional: while the node is revisedWhy the node differs from the DST estimate. Saves when the user leaves the box; also entered in the Failure mode summary.

The chart and the Revised Estimate column of the SRP table update as the user types, and the revisions save shortly after each change. Revisions do not recalculate the system response; DST combines the revised nodes into the Revised Estimate curve, which becomes the active SRP.

Three buttons undo revisions, each after a confirmation dialog whose Continue and revert button proceeds:

  • Revert to DST Estimates in the node dialog clears that node's revised estimates and keeps its headwaters.
  • Revert to DST Headwaters in the node dialog replaces that node's custom headwaters with DST's.
  • Revert to DST Estimates beside the Nodal System Response heading clears every revised estimate and custom headwater of the location.
caution

Nodal revisions belong to the calculated results. When an input on this page or another page changes and the system response recalculates, DST clears the location's nodal revisions together with its results and verification. DST reports a change on another page in a notice; one example reads "Dam Information, Operational Data or Failure Mode Screening inputs changed since these results were calculated. The results, nodal adjustments, and SRP verification were cleared; the analysis will recalculate automatically." The first sentence differs between failure modes. The justifications of revised nodes are kept.

Calculation currency​

DST records which version of the System Response calculation produced each result. When stored results cannot be confirmed as current, the System Response section shows a notice in place of the results; DST withholds the chart and the copy and download buttons; and the location's status is not Defined. Table lists the notices.

When DST refreshes the results, the notice clears on its own. When results were cleared while no one had the page open, the page shows the reason in a notice when it next opens, and recalculates. Out-of-date results cannot be verified or exported, and they keep the screening from being submitted (see Chapter 4, Working in DST).

User-defined SRP​

In User Defined SRP mode the page shows a table of points and a chart of the curve they define. The user enters the curve directly, or pastes it from a spreadsheet (see Chapter 4, Working in DST).

Table describes the table's columns.

Table: User-defined SRP table columns
FieldUnitsRequiredDescription
Headwater ElevationftRequiredThe horizontal axis of the page: Headwater Elevation (ft), Overtopping Depth (ft) on PFM-01 or Pool Elevation (ft) on the event-tree pages. Values must increase down the table.
Probability—RequiredThe system response probability at that point, from 0 to 1, entered in scientific notation or as a decimal. Values should not decrease down the table.

The table starts with two rows. Until it holds values the chart reads "Enter values in the table to plot the system response curve." The table saves shortly after each change and becomes the active SRP. DST reports these warnings in the page messages: "SRP curve is empty."; a first headwater above the lowest hazard headwater, suggesting a point at or below it with probability 0; a probability that decreases between two points ("SRP curves should be monotonically non-decreasing."); a probability below 0 or above 1 ("Probabilities must be between 0 and 1."); and headwaters that are not strictly increasing.

Event Trees​

PFM-11, PFM-12, PFM-13, PFM-17, PFM-18, PFM-20, PFM-22 and PFM-23 define their system response with an event tree, as does PFM-21 when the dam has a concrete type but no Gravity or Roller-Compacted Concrete type (see Chapter 28, PFM-21: Concrete Dam Instability): the team assigns a probability to each node of the tree at each of a set of reservoir stages, and DST multiplies them along each pathway to breach. These pages share one layout, whose sections are numbered: 1 Stages to evaluate, 2 Event tree evaluation, and then System Response. Each failure mode's chapter lists its own stages, nodes, questions and branches. The SRP mode control reads Event tree and User defined.

Every entry on an event-tree page saves automatically and clears the location's verification. A change to a source of a default stage, such as the normal pool on the Stage Duration page, also clears it.

Stages​

The Stages to evaluate section lists the reservoir stages at which the tree is evaluated, lowest first. Its description reads "Stages are listed lowest first. At and below the zero point, the system response is fixed at 1.00E-16 and nodes take no probability."

Figure shows the section, and Table describes its columns.

Table: Stages to evaluate columns
FieldUnitsRequiredDescription
Zero point—RequiredThe stage at and below which the system response is fixed at 1.00E-16. Default: the lowest stage. Stages at or below it are grayed.
ElevationftRead-only or RequiredDefault stages: taken from their source, or Source missing (amber italics) until the source is complete. Added stages: entered by the user.
Stage—Read-only or OptionalThe stage name. Added stages: a description of up to 200 characters; a blank description becomes Added stage.
Source—Read-onlyWhere a default stage comes from, for example "Spillway crest, Dam Data", or "Added, every node" or "Added, Node 3 only" for an added stage.

Default stages come from the failure mode and cannot be edited or deleted. To add a stage for every node:

  1. 1The user selects Add stage. A new row opens with an elevation box and a Description box.
  2. 2The user enters the elevation and, optionally, a description.
  3. 3Pressing Enter, or leaving the row, adds the stage in elevation order. Escape or the × button cancels it.

An added stage's elevation and description stay editable in place. The trash icon deletes it ("Delete this stage and its entered values"). A stage added from a node's panel applies to that node only (see Nodes).

When the source of a default stage changes, a notice above the table reads, for example, "The Normal Pool source changed. It now resolves to 1,021.50 ft. The stage stays at 1,018.00 ft until you move it." Move stage to (with the new elevation) moves the stage; Dismiss keeps it where it is.

Event tree diagram​

The Event tree evaluation section opens with a diagram of the tree and a count such as "3 of 5 nodes complete" in its heading.

Figure shows the diagram with a node selected, and Table describes each numbered region.

The diagram reads left to right: a fan labeled Flood, the numbered nodes with their titles beneath, and a red triangle for breach. In a tree with more than one pathway, the line splits after the branching node into an upper Yes row and a lower No row. Each node's circle shows its state:

  • Steel blue with its number: not started.
  • Pale amber with an amber ring: started; some values or the rationale are entered.
  • Green with a white check: complete; it has a probability at every stage above the zero point and an estimate rationale.

A node that mirrors another is tagged Mirrors or Partly mirrors beneath its title (see Mirrored nodes). Nodes can also be selected with the keyboard: Tab moves between them, and Enter or Space opens one. With no node selected, the panel reads "No node selected" and "Select a node in the event tree to view and assign its probabilities."

Nodes​

The node panel is headed with the node's number and title, followed by the question the node asks. It has one row per stage of the node: the default stages, the stages added for every node and the stages added for this node only. A node that does not depend on the stage has a single row, All stages, marked Pool independent. Table describes its inputs.

Table: Node panel inputs
FieldUnitsRequiredDescription
Probability—Required: every stage above the zero pointThe probability of the node's Yes outcome at the stage, from 0 to 1. Saves when the user leaves the box; a 0 is stored as 1.00E-16. Stages at or below the zero point show a dash and take no value.
Slider—OptionalSets the probability by dragging, on a scale marked Virtually Impossible (0.001), Very Unlikely (0.01), Unlikely (0.1), Neutral (0.5), Likely (0.9), Very Likely (0.99) and Virtually Certain (0.999).
Estimate rationale—RequiredA rich-text case for the node's estimates across all of its stages. Saves two seconds after the user pauses typing.

Add stage to this node adds a stage that only this node uses; the user enters it in the same way as an added stage (see Stages) and appears in the Stages table as Added, Node N only. Its trash icon deletes it with its value. Pool-independent nodes have no such button.

Previous node and Next node step through the nodes, starting with those shared by every pathway and then following each pathway, and wrap around at the ends. A node's probabilities should stay the same or increase from one stage to the next (see Event tree messages).

Mirrored nodes​

In trees whose pathways repeat a node, the repeated node can mirror its source node, so the team enters the values once. Mirroring is off by default. The node panel of such a node has a check box, for example Mirror Node 2a:

  • Turning it on. The node follows its source's values and rationale. Mirrored values show a link icon ("Mirrored from Node 2a"), and the rationale shows "Shared with Node 2a until you edit it here."
  • Overriding one stage. Entering a value at a stage overrides it for that stage only, and the node becomes Partly mirrors. A re-link icon beside the overridden value discards it and follows the source again ("Discard this value and follow Node 2a again"). Re-link all discards every override of the node.
  • Editing the rationale on the mirroring node replaces the shared rationale with its own.

Event tree system response​

The System Response section of an event-tree page shows a table and a chart once every node has a probability at every stage above the zero point and the stages and probabilities have no errors. Until then it reads "No system response curve yet" and "The curve appears once every node has a probability at every stage above the zero point and the stages and probabilities have no errors."

Figure shows the results of a tree with two branches.

  • Table. One row per stage, with the columns Stage (ft), one column per branch (Branch a, Branch b) when the tree has more than one pathway, and Total SRP. The information icon on a branch header names the pathway's nodes and shows the tree with the pathway highlighted; the icon on Total SRP explains how the branches combine. Resting the pointer on a branch value shows its share of the total, such as "62.5% of the total". Stages at or below the zero point are grayed.
  • Chart. The curves plotted against Pool Elevation (ft) on a logarithmic probability axis, with the same zoom, reset and download controls as the other SRP charts (see SRP charts).

The total becomes the location's active SRP in Event tree mode (see Active SRP). Event-tree pages have no nodal revisions; the team enters the node probabilities directly.
