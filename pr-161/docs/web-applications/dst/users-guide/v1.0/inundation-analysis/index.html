Dam Screening Tool

Inundation Analysis

The Inundation Analysis page, at Consequences > Inundation Analysis, defines and runs the flood simulations. An analysis is a named set of loading levels, which are reservoir water-surface elevations. Each loading level is simulated in HEC-RAS with the analysis's boundary conditions and plan settings, and the analysis's results are one flood map per loading level.

Figure shows the page with an analysis's dam boundary conditions open, and Table describes each numbered region.

Table: Inundation Analysis page regions
#RegionDescription
1Analysis tilesOne tile per analysis, with its status dot and its Edit, Run, Copy and Delete icons, and the Add analysis tile.
2Boundary-condition listThe features of the active analysis that take a boundary condition.
3Simulation bandThe active analysis's run status, with a row per loading level and the icons for results, details and download.
4Boundary conditions panelThe selected feature's boundary conditions in the active analysis.
5Depth over time at a pointReads the depths over time at a point selected on the map.

The page is a map (see The map) with these regions:

  • Analysis Configuration, a panel at the upper left, with a tile for each analysis, the boundary conditions of the selected analysis, and its simulation status.
  • [Feature] Boundary Conditions, a panel at the right that opens when a dam, model area, river or coastline is selected on the map or in the list. The geometry itself is read-only on this page.
  • The Depth over time at a point tool in the map toolbar, and the results layers in the legend.

Analyses​

Each analysis is a tile in the Analysis Configuration panel; selecting a tile makes it the active analysis. The icons on a tile are Edit analysis, Run the simulation, Copy analysis and Delete analysis. A status dot shows the last simulation: green "Simulated.", amber "Inputs have changed since the last simulation.", or red when the last simulation did not complete or could not start.

Add analysis creates an analysis named "Set N" and opens its Edit Analysis dialog. Copy analysis copies the plan settings, loading levels and boundary conditions into "[name] (Copy)". Delete analysis asks for confirmation; it deletes the analysis and all of its loading levels, and cancels a simulation that is running.

Edit Analysis​

The Edit Analysis dialog holds the analysis name, its plan settings and its loading levels, and saves them with Save; Cancel discards the changes. Table lists its fields.

Table: Analysis name and plan settings
FieldUnitsRequiredDescription
Analysis Name—RequiredA descriptive name, up to 200 characters, unique in the screening.
Run time after inflow endshrsOptionalHow long the model keeps running after the last inflow ends, in whole hours from 0 to 8760. Blank estimates it from the terrain and land cover.
Equation set—RequiredDiffusion wave (faster), the default, or Full momentum, SWE-ELM (slower).

Mapping IntervalminRequiredHow often the model saves a snapshot of the flood: 5, 10 (the default), 15 or 30 minutes.

Maximum Courant number—Conditional: when the time step is adjusted automatically1, 2, 3 (the default) or 5. The lower limit is a third of it.

The Loading Level table lists the analysis's loading levels, one row each, with the columns Loading Level (the pool elevation, a positive number, unique in the analysis) and an optional Label of up to 100 characters. Rows sort by loading level and are added, pasted and deleted like any DST table (see Tables). A new loading level copies the boundary conditions of the lowest existing level, without its per-level values, and starts its reservoir at the loading level. Removing a loading level deletes its results and its consequence runs.

Boundary conditions​

The panel below the tiles lists the features that can take a boundary condition in the active analysis: the dam centerline, the model area, the rivers that enter the model area, and the coastlines. Selecting one opens its boundary conditions at the right, under the heading "[feature] ([analysis])". Settings apply to every loading level of the analysis, except the values entered in tables with one row per loading level. The boundary conditions save as they are entered; there is no Save button.

Dam​

Boundary Condition Type is None (the default), Hydrograph or 1D Reservoir:

  • Hydrograph applies a dam-breach hydrograph directly to the 2D mesh. Its location is set with Latitude and Longitude, or with the crosshair button and a click on the dam centerline, and Width is the breach width over which it enters the mesh. Hydrograph Type and its tables are described in Hydrographs.
  • 1D Reservoir routes an inflow through a reservoir and a breach, on three tabs: Reservoir, Inflow and Breach.

The Reservoir tab states how the reservoir releases water: through the Stage-Outflow curve on the Operational Data page, or, without one, only over the dam crest. Storage & outflow curves shows the Operational Data curves the reservoir uses, read-only, with a link to edit them there. Its table gives, for each loading level, the Initial WSE (the reservoir level at the start of the simulation, defaulting to the loading level) and, when the outlet curve is in use, the Release at start. A red message explains any problem in the Stage-Outflow curve that stops a run.

The Inflow tab's Inflow Hydrograph check box routes an inflow hydrograph into the reservoir (see Hydrographs). The Breach tab's Breach check box turns the breach on.

Breach​

The breach fields appear on the Breach tab once Breach is checked. Table lists them. Breach Method decides where the breach geometry comes from: User Defined takes the development time, bottom width and side slopes for each loading level, and FEMA Defaults calculates them from the dam type, height and length (FEMA P-946, Table 9.3) for every loading level. Values entered under User Defined are kept while FEMA Defaults is selected.

The Breach Geometry plot draws the terrain along the dam, the dam crest, the breach location and each loading level's breach trapezoid, and the initial pipe for a piping failure. Under User Defined, the calculator icon opens the Breach Calculator, which estimates the breach with the MacDonald-Langridge-Monopolis or the Xu & Zhang / Von Thun method from the failure mode, the top of dam, breach bottom and pool elevations, the pool volume at failure, and the method's own dam inputs. Calculate shows the Calculator Results, and Apply Results writes them to every loading level.

Model area, rivers and coastlines​

  • Model area. Normal Depth Slope (default 0.001, greater than 0 and at most 1) is the outflow boundary that lets water leave the model area around its perimeter. The table's Initial water level for each loading level is left blank; the simulation service cannot yet start a 2D area wet, and a run with a value refuses to start.
  • River. Upstream Boundary is None or Hydrograph, an inflow series for the river. A river that crosses the dam takes its flow from the dam, and a river that starts inside the model area cannot take an inflow.
  • Coastline. Boundary is None or Hydrograph, a stage series applied along the model area edge between the ends of the coastline. Stages may be negative.

Hydrographs​

A hydrograph is a series of values over time. In an inundation analysis it is the water entering the model at a boundary: a flow in cubic feet per second (or cubic meters per second) against hours from the start of the simulation, or, at a coastline, a water surface elevation. Four boundary conditions take one, and all four use the same editor:

  • The Inflow tab of a dam's 1D Reservoir boundary condition, the flood flowing into the reservoir. This is the most common use, and the rest of this section describes it.
  • A dam's Hydrograph boundary condition, a breach outflow applied directly to the 2D mesh (see Dam).
  • A river's Upstream Boundary, the flow entering the model area along the river.
  • A coastline's Boundary, a stage series along the model area edge.

What the inflow hydrograph does​

Each loading level of an analysis represents the reservoir reaching one pool elevation, and its inflow hydrograph is the flood that takes it there. For each loading level, HEC-RAS starts the reservoir at its Initial WSE on the Reservoir tab and routes the inflow hydrograph into it:

  • The reservoir rises while the inflow exceeds the outflow, by the volumes in the Stage-Storage curve on the Operational Data page (see Operational Data).
  • It releases water through the Stage-Outflow curve, when the screening has one, and over the dam crest once the pool is above the top of dam.
  • The highest pool the routing reaches is the Max pool in the dam results (see Dam results). It is set by the hydrograph's peak and its volume together, not by the peak alone.
  • A breach with an Elevation trigger starts when the pool reaches the trigger value, so the hydrograph also decides when, and whether, the dam breaches.

The hydrograph also sets the length of the simulation. The simulation runs from time zero to the end of the longest hydrograph (or of the breach, if it ends later), plus the Run time after inflow ends in Edit Analysis (see Edit Analysis), which gives the flood time to travel through the model area. Simulation details reports the resulting window, for example "Simulation window 01Dec2099 0000 to 02Dec2099 0200 (longest hydrograph or breach 20 h + travel time 6 h)".

Without an inflow hydrograph the reservoir can only fall from its Initial WSE. A breach whose trigger elevation is above the Initial WSE then never starts, and the run warns that the reservoir "never rises that far and the dam does not breach in this simulation." With an inflow and a Stage-Outflow curve, DST estimates the highest pool before the run, by level-pool routing, and gives the same warning when that estimate stays below the trigger. Either way the run goes ahead, because a level at which the dam holds can be intended.

The Inflow tab​

The Inflow Hydrograph check box turns the inflow on for every loading level of the analysis; cleared, the tab reads "No inflow hydrograph is defined for this boundary condition, click the checkbox to define one." Once it is checked, Hydrograph Type chooses how the hydrograph is entered, Trapezoidal (the default) or Tabular, for all of the analysis's loading levels at once. The chart plots one line per loading level, Flow against Time (hrs), and follows the values as they are entered. Figure shows the tab with tabular hydrographs, and Table describes each numbered region.

Trapezoidal hydrographs​

A trapezoidal hydrograph is the simplest flood shape: a straight rise from a base flow to a peak flow, a flat top where the peak is held, and a straight fall back to the base flow. Plotted against time it is a trapezoid, which gives the type its name. It takes four values for each loading level, in a table with one row per level (Table).

Table: Trapezoidal hydrograph values
ColumnUnitsRequiredDescription
Loading Levelft or m, datumRead-onlyThe loading level the row applies to.
Basecfs or cmsRequiredThe flow at the start and at the end of the hydrograph.
Base TimehrsRequiredThe total length of the hydrograph, from time zero to the end of the fall. Must be greater than zero.
Peakcfs or cmsRequiredThe highest flow, held across the flat top.
Peak TimehrsRequiredHow long the peak is held. Must not be more than the Base Time.

DST builds the shape from these four values. The rise and the fall take equal times, each half of what is left after the peak is held:

  • From hour 0 the flow rises in a straight line from Base to Peak over (Base Time − Peak Time) ÷ 2 hours.
  • It holds at Peak for Peak Time hours.
  • It falls in a straight line back to Base, reaching it at Base Time, where the hydrograph ends.

For example, a Base of 2,500 cfs, a Base Time of 20 hrs, a Peak of 150,000 cfs and a Peak Time of 4 hrs rises from 2,500 to 150,000 cfs over the first 8 hours, holds 150,000 cfs from hour 8 to hour 12, and falls back to 2,500 cfs at hour 20. A Peak Time of 0 makes a triangle, and a Peak equal to the Base makes a constant inflow for the whole Base Time. A Peak Time greater than the Base Time is marked in red with "Peak Time must be less than or equal to Base Time."; that level is left off the chart, and the run will not start until it is corrected.

A trapezoidal hydrograph suits a first pass, when no flood hydrograph is available yet, and a steady inflow, such as a normal-pool level where the reservoir only passes its usual release. Its straight limbs and flat top are not the shape of a real flood, so the timing of the pool and of the breach is approximate.

Tabular hydrographs​

A tabular hydrograph is any shape entered point by point. The loading-level tabs above the table choose the level, and each level has its own Time (hr) and Value columns. Times are hours from the start of the simulation and need not be evenly spaced; HEC-RAS interpolates between them. A hydrograph needs at least two rows, and neither its times nor its flows may be negative. The table works like any DST table: rows can be added, inserted and deleted, and time and flow pairs copied from a spreadsheet can be pasted in, which grows the table as needed (see Tables).

A tabular hydrograph suits a flood hydrograph from another source: the outflow of a hydrologic model such as HEC-HMS, an inflow design flood, a recorded flood, or a synthetic storm hydrograph scaled to each loading level. The hydrographs in

Figure are of the last kind: one 20-hour storm hydrograph, scaled for each loading level.

How the hydrograph reaches HEC-RAS​

DST sends the inflow hydrograph to HEC-RAS as the flow into the reservoir's storage area, with a 5-minute hydrograph interval. A trapezoidal hydrograph goes as its four values and a tabular one as its points; nothing is smoothed or extended. The hydrograph ends at its last time, and the simulation then continues for the Run time after inflow ends.

Before a run starts, DST checks each loading level's hydrograph and stops the run with the reason when it is incomplete: a trapezoidal hydrograph without all four values ("It needs base and peak values and durations."), a peak held longer than the base duration, or a tabular hydrograph with fewer than two points or with negative times or flows.

Shaping an inflow hydrograph​

  • Start at the reservoir's release. Begin the hydrograph at the flow the reservoir releases at its Initial WSE, the Release at start on the Reservoir tab, so that the pool holds steady until the flood arrives.
  • Make the pool reach the loading level. A loading level stands for the reservoir at that pool elevation, so shape each level's hydrograph so that the routed pool peaks at, or just above, the loading level. After a run, compare the Max pool in the dam results with the loading level, and scale the hydrograph up or down and run again if they differ.
  • Reach the breach trigger. For a level whose breach starts on an Elevation trigger, the pool must reach the trigger value. Heed the warning when DST estimates that it will not.
  • Keep it no longer than needed. The run time grows with the simulation window, and so with the hydrograph's length. End the hydrograph once the pool has peaked and the flow has receded, and let the Run time after inflow ends carry the flood through the model area.
  • Use one shape across the levels. Scaling one hydrograph shape to each loading level keeps the levels comparable, so that the differences in their results come from the size of the flood rather than its shape.

Running an analysis​

The flood simulations are one of the two places in DST where the user starts a calculation (see Automatic Calculation); nothing runs on its own. Each analysis tile has a play button, Run the simulation (Run the simulation again once it has run), which simulates every loading level of that analysis. The button is unavailable, with the reason, when the analysis has no loading levels ("Add a loading level to run the analysis") or when simulations are not available. While the run is in progress the button becomes a spinner; selecting it cancels the run ("[status]. Click to cancel."). There is no separate retry: a failed or cancelled analysis is run again with the same button.

Before starting, DST checks the model and refuses to start with the reasons when, for example, the mesh is not computed, there is no terrain or land cover, no inflow is defined, or a breach is incomplete. Warnings that do not stop the run, such as a breach the reservoir never reaches, are reported as the run starts.

The [analysis] Simulation band under the boundary conditions shows the run's status: Waiting for a model server, Sending files, Queued, Building model, Running (with a percentage), Complete, Failed, Cancelled, Timed out or Lost. Its rows show each loading level, as Computed, Did not compute, Not run or Not verified, and its icons open the dam results, open Simulation details, and download the HEC-RAS project. When inputs change after a run, the status shows a warning: "Inputs have changed since this simulation ran. The depth grids show the earlier inputs; run the analysis again to update them."

Figure shows the details of a completed simulation.

Simulation details opens a dialog with the run's status, timing and HEC-RAS version; any reasons it could not start, errors, warnings and values built differently from what was asked; a Loading levels table with each level's result, volume error, largest cell error, water that left the model area and compute time; and folded sections for how the model was built and the console output. Download HEC-RAS project saves the project, results and logs as a zip file.

Results on the map​

The legend's Inundation Results group lists, for each analysis and loading level, Maximum depth, Depth over time and Water leaving the model. Turning on Depth over time shows a player with Play, Pause, the previous and next outputs, a Simulation time slider, a speed in simulation hours per second, Loop and a blend toggle. Each frame is the water surface at one mapping output time.

Depth over time at a point in the toolbar reads the depths at a point selected on the map. Its panel plots depth over time for each loading level of the chosen Analysis, with an Arrival depth (0.5 ft by default) and a table of when each level reaches that depth, its peak depth and time, and how long it stays that deep. Download CSV saves the depths.

Dam results​

The dam results dialog, [analysis] Results, opens from the chart icon in the simulation band or the Results button on the dam's boundary conditions. It lists, for each loading level, when overtopping and the breach started, when the breach was fully formed, the peak outflow and its time, the maximum pool and tailwater, and the water released. A time plot, Outflow through the dam, shows the outflow series the run kept, such as the flow through the breach, and the pool and tailwater, with Flow, Elevation and Both, Event and Whole simulation, and Compare levels; a cross-section of the breach follows the time bar. The table copies to the clipboard and downloads as CSV.

Figure shows the dam results of an analysis with a piping breach.

Changing an input after a run does not clear its results; the analysis is marked out of date until it is run again.
